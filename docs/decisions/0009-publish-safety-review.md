# 0009 — Publish-safety review: this repo is safe to make public

**Status**: accepted • **Date**: 2026-07-29

## Context

`rpi` is one of three repos heading for public visibility (with `ros` and `faves`). The
estate registry in `shed` tracks the intent and defines the gate every candidate must pass
before a flip. `rpi` was chosen as the **pilot** — smallest surface — so the checklist is
proven here first.

This review also discharges the pending **"safe to share"** review that
[ADR 0005](0005-sbom-cyclonedx.md)'s release track leaves gating the PyPI publish
(see ROADMAP, *Tag and publish*).

**Flipping visibility is not this review's to do.** Under the CLAUDE.md floor, making a
private repo public is an always-stop-and-confirm action. This ADR produces the evidence;
the owner rules.

Scope note: this is about **what the repo publishes**. It is a different question from
[ADR 0008](0008-crowd-upload-anonymisation.md), which asks what card data may leave a
*user's* machine. ADR 0008 remains open and is **not** settled here.

## Decision

**Verdict: SAFE TO PUBLISH**, with the fixes in this change applied.

Each gate, with the evidence rather than an assurance:

| # | Gate | Evidence |
|---|------|----------|
| 1 | leakscan | **11 → 0.** All 11 triaged as false positives; each carries a narrow marker with a stated reason. |
| 2 | secretscan | **0**, re-confirmed at the repo root. Cover *proved*, not assumed — a planted multi-shape canary fired 4 findings, then scanned clean once removed. |
| 3 | Full history | **233 unique blobs** across all 63 commits extracted and scanned. secretscan **clean**. leakscan: 80 findings, all four of the same benign classes. |
| 4 | Licence | Apache-2.0 declared and GitHub-detected; `licenscan` clean. **Zero** third-party imports; `dependencies = []`. No vendored code, so no copyleft to inherit. |
| 5 | Reconnaissance | Swept for addressing, hostnames, machine names, estate services and absolute paths: **nothing**. No card serial is ever committed. |
| 6 | README and docs | Reads as a public project. No estate-insider assumptions; no references outside the repo. |

### Gate 1 — the 11 leakscan reds, triaged

Every one a false positive. None removed as data; each exempted narrowly:

- **8 × author byline** (`Mike Clements, Competitive Edge`) in the per-file headers,  <!-- leakscan:allow: quotes this review's own triaged findings (author byline / "2 Lane" PCIe comment / "12:00:00" fixture clock) — evidence, not data. See ADR 0009. -->
  `pyproject.toml`, the man page and a build artefact. This is deliberate attribution — the
  one place a name belongs in an open-source project, and it already ships in the PyPI
  metadata by design. Inline `leakscan:allow:` marker on each line; the man page uses a
  troff `\"` comment, so the rendered page is unchanged (verified with `mandoc`).
- **1 × `nz-address`** at `src/rpi_sdinfo/cli.py` — matched `2 Lane` in a comment reading  <!-- leakscan:allow: quotes this review's own triaged findings (author byline / "2 Lane" PCIe comment / "12:00:00" fixture clock) — evidence, not data. See ADR 0009. -->
  *"PCIe Gen.4 x 2 Lane"*. A lane count, not a street.  <!-- leakscan:allow: quotes this review's own triaged findings (author byline / "2 Lane" PCIe comment / "12:00:00" fixture clock) — evidence, not data. See ADR 0009. -->
- **2 × `ipv6`** at `tests/test_helpers.py` — matched `12:00:00`, a clock time inside a  <!-- leakscan:allow: quotes this review's own triaged findings (author byline / "2 Lane" PCIe comment / "12:00:00" fixture clock) — evidence, not data. See ADR 0009. -->
  `dumpe2fs` test fixture.

The build artefact (`src/*.egg-info/`) is the sole `.leakscanignore` entry: it is
regenerated by `pip install -e .`, is already in `.gitignore`, and merely restates the
byline from `pyproject.toml`.

### Gate 3 — what the history holds

The only finding of substance is that `LICENSE` held **GPL-2.0** before commit `2e4ed88`
relicensed to Apache-2.0. That is sound: `git log` shows a **single human author**
(`Mike Clements`), with the only co-author trailers being Claude models. Sole copyright  <!-- leakscan:allow: quotes this review's own triaged findings (author byline / "2 Lane" PCIe comment / "12:00:00" fixture clock) — evidence, not data. See ADR 0009. -->
holder, so the relicence was his to make. The two `nz-address` hits in that blob are the
Free Software Foundation's own Boston address inside the GPL text.

**No history rewrite is needed, and none was performed.**

## Rejected

- **A blanket `.leakscanignore`** covering the source tree. Rejected: it would silence
  future, genuine findings in the same files. Per-line markers keep each exemption visible
  in the diff and greppable.
- **Removing the author byline** to clear the reds. Rejected: it is attribution, not
  leakage — and Apache-2.0 practice expects it.
- **Rewriting history / a fresh-history repo.** Rejected as unnecessary on the evidence: no
  credential, no personal data and no unlicensed third-party code appears in any of the 233
  blobs. Had the evidence gone the other way, that call would have been the owner's, not
  this review's.
- **Trimming the CI matrix.** Out of scope and pointless: the spend is US$0.52/month and
  going public takes it to zero.

## Consequences

- The floor's CI failure is **resolved as a side effect**: the `floor` workflow had been
  red on every run, `BLOCKED by: leakscan` on the three structural findings. It now passes.
- **Residual risks the owner accepts on a flip** — all judged acceptable, none blocking:
  - **Real name and company become public**, attached to the code and to the PyPI metadata.
    Deliberate, but it is a real identity disclosure.
  - **A personal commit-author email is in history** — the address is in the metadata of all
    63 commits (`git log --format=%ae` shows it; it is deliberately not reproduced here, so
    this review does not add a fresh grep-able copy to the tree). Normal for git and
    unavoidable without a rewrite. GitHub's `noreply` address is the fix for *future* commits
    if that address is not meant to be public.
  - **The repo's own weaknesses are published**, above all that the Raspberry Pi path is not
    hardware-tested. README states this plainly, which is the honest posture.
  - **CI is visibly red on Windows** — pre-existing and unrelated to publish safety: the
    suite calls `os.geteuid` and `os.pwrite`, neither of which exists on Windows. Lint is
    also red on two `E402`s that a newer `ruff` began enforcing. Publishing does not *create*
    a defect, but it does put a red badge on the front page. Fixing it is a separate track.
